## 1. Problem statement

Organisations that own more than a handful of computers lose track of them.
Devices are reassigned between staff, moved between buildings, sent for repair
and eventually retired, and unless that is recorded somewhere it becomes
impossible to answer basic questions: *which laptops are unassigned right now?*
*what is sitting in the store room?* *how much have we spent on servers?*

AssetTrack is the frontend of a system that answers those questions. A user
records each physical asset once, then keeps its record current as the asset
moves through its lifecycle.

## 2. Scope

**In scope for Part 1**

- A single-page React application.
- Full CRUD over an in-memory collection of asset objects.
- Search, filter, sort and summary views.
- Client-side validation of user input.
- An About page identifying the team.

**Out of scope for Part 1** (deferred to Part 2)

- Persistence — data resets on page reload, which is intentional.
- A backend API, authentication, user accounts and permissions.
- File uploads, barcode scanning, audit trails, exports.

## 3. Domain model

A single entity, `Asset`:

| Field | Type | Required | Rules |
|---|---|---|---|
| `id` | string (UUID) | yes | Generated by the system, never editable |
| `name` | string | yes | 2–80 characters |
| `tag` | string | yes | 3–20 characters, `A–Z a–z 0–9 -` only, **unique** |
| `category` | enum | yes | Laptop, Desktop, Monitor, Server, Printer, Networking, Mobile Device, Peripheral |
| `status` | enum | yes | In Use, In Storage, Under Maintenance, Retired |
| `department` | enum | no | IT, Engineering, Finance, HR, Marketing, Operations, Unassigned |
| `assignedTo` | string | no | Person or team holding the asset |
| `location` | string | no | Building / room / rack |
| `purchaseDate` | ISO date | no | Must be a valid date, not in the future |
| `purchaseCost` | number | no | ≥ 0 and ≤ 10,000,000 (SAR) |
| `notes` | string | no | ≤ 500 characters |
| `createdAt` | ISO datetime | yes | Set by the system on creation |
| `updatedAt` | ISO datetime | yes | Refreshed by the system on every update |

## 5. Non-functional requirements

| ID | Requirement | How it is met |
|---|---|---|
| NFR-01 | **Usability** — every action reachable in at most two clicks from the menu. | Four top-level menu items; row-level Edit/Delete buttons. |
| NFR-02 | **Accessibility** — usable with a keyboard and a screen reader. | Every control has a label; `aria-sort` on sortable headers; `role="status"` live regions; `aria-invalid` on failed fields; visible focus rings. |
| NFR-03 | **Responsiveness** — usable from 360 px upward. | CSS Grid with `auto-fit`; the navbar stacks and the table scrolls horizontally below 720 px. |
| NFR-04 | **Performance** — filtering stays smooth as the collection grows. | The search/filter/sort pipeline is memoised with `useMemo`; callbacks are stabilised with `useCallback`. |
| NFR-05 | **Maintainability** — business rules testable without the DOM. | All rules live in pure functions in `assetUtils.js` and `assetReducer.js`; 37 of the 65 tests need no rendering. |
| NFR-06 | **Portability** — runs anywhere Node 18+ runs. | No native dependencies; `npm install && npm run dev`. |
| NFR-07 | **Extensibility** — swapping in a real backend must not touch the UI. | The data layer is behind a four-function context interface. |

## 6. User stories

1. As an IT administrator, I want to register a newly purchased laptop so that it appears in the inventory from day one.
2. As an IT administrator, I want to change an asset's status to *Under Maintenance* so that colleagues know it is unavailable.
3. As an IT administrator, I want to search by asset tag so that I can find one device among hundreds.
4. As an IT administrator, I want to filter to *In Storage* laptops so that I can allocate a spare machine to a new employee.
5. As an IT administrator, I want to delete a disposed asset, but be asked to confirm, so that I do not lose a record by mis-clicking.
6. As a department manager, I want to see how many assets my department holds and what they cost.
7. As the course instructor, I want to see who built the application and their student IDs.

## 7. Assumptions and constraints

- One user at a time; no concurrent editing, so no conflict resolution.
- Costs are in Saudi Riyals (SAR).
- Asset tags are issued by the organisation; the app only checks format and uniqueness.
- Data loss on reload is expected in Part 1 and is not a defect.
- English-only interface, left-to-right.
